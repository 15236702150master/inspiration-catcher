# 转写标注工作区设计说明

本设计采用用户确认的 C 模式：**原始转写只读保留、标注独立叠加、个人加工稿独立编辑**。

完整实现记录保存在本地开发工作区；公开仓库只保留本设计摘要，避免带入
机器路径、运行日志和个人交接资料。

核心决策：

- 原始转写和每次 AI 阅读排版都改为不可变版本。
- 标注以不可变 raw transcript 为 canonical source，使用“块 ID + UTF-16 位置 + 原句 + 前后文 + 文档校验值”复合锚点；AI 阅读版只维护展示锚点。
- AI 重新排版后只做可审计的重新定位；歧义标注进入待确认，绝不猜测挂载。
- 我的感想与个人加工稿分开；加工稿采用 Tiptap JSON、自动保存、离线重试和版本冲突处理。
- 正式功能建立在 SQLite 事务存储上，不继续依赖整份 JSON 文件覆盖；旧标签、任务、AI 正文和待实践数据一并迁移校验。
- 前端引入可重复构建的 Vite + lockfile 交付链，Tiptap、Markdown AST 与清洗库全部本地打包。
- 首页和详情页共用同一个转写工作区，桌面使用批注轨道，手机使用底部工具栏和批注抽屉。
- 手机验收同时覆盖 Chromium/WebKit 自动化，以及 Android Chrome、iOS Safari 真实设备长按、键盘和旋转。

实施必须先完成数据库迁移与锚点测试，再开发高亮工具条；这一顺序是避免返工的主要保障。
